# RunWitness v0.0.6 Release Scope

Status: Release candidate contract

v0.0.6 introduces the first explicit Run-to-Run semantic comparison surface on top of stable cross-Run Finding identity.

## Stable public surface inherited from v0.0.5

All v0.0.5 behavior remains compatible except for the expected version string moving to v0.0.6:

- universal Run execution and Git/process capture;
- opt-in OpenTelemetry Evidence through `--otel`;
- explicit Rails runtime observation through `--rails`;
- normalized OpenTelemetry and Rails Evidence;
- semantic runtime Findings;
- deterministic cross-Run Finding identity;
- existing `runtime.no_errors` fail gate;
- target process exit-code preservation;
- verdict and CLI exit-code semantics;
- real upstream `otlp-mcp` interoperability gate;
- real Rails 8.1 / Ruby 3.4 interoperability gate.

## New stable surface in v0.0.6

RunWitness supports explicit local baseline comparison:

```text
runwitness run --baseline <run_id> -- <command> [args...]
```

A successfully resolved baseline is recorded in the current Run:

```json
{
  "baseline": {
    "run_id": "<baseline-run-id>"
  }
}
```

The finalized semantic Finding sets are compared by stable `finding_id` identity:

```text
new       = current - baseline
resolved  = baseline - current
unchanged = current ∩ baseline
```

The current Run records deterministic unique, lexicographically sorted lists in:

```json
{
  "diff": {
    "new": [],
    "resolved": [],
    "unchanged": [],
    "regressed": [],
    "improved": []
  }
}
```

For v0.0.6, `regressed` and `improved` remain reserved and empty. Metric-aware comparison semantics are explicitly deferred.

Baseline comparison is source-agnostic and occurs over the finalized Finding set, so current OpenTelemetry and Rails Findings share the same comparison semantics.

## Baseline reliability contract

Baseline selection remains explicit and local only.

A requested baseline that is missing, unreadable, malformed, or does not match the requested Run ID MUST fail before target execution and before a new Run is created.

When the current Run ends with verdict `error` because RunWitness or a required adapter could not complete observation reliably, RunWitness MUST NOT claim Findings were resolved. The selected baseline may be recorded, but `diff` is omitted.

A reliably observed target failure may still produce a diff.

## Gate semantics

v0.0.6 comparison is descriptive. It does not weaken or rewrite existing absolute gates.

An unchanged current runtime error still triggers `runtime.no_errors`. A resolved baseline error does not trigger a current gate when the current Run no longer contains that Finding.

Baseline-aware policies such as "fail only on new Findings" are deferred.

## Version contract

The stable release reports:

```text
RunWitness v0.0.6
```

`--version` remains side-effect free and MUST NOT create a Run.

## Why this release exists

Stable Finding identity becomes directly useful when two Runs can answer:

```text
same logical problem     -> unchanged
current-only problem     -> new
baseline-only problem    -> resolved
replaced problem         -> one resolved + one new
```

This is the first stable step from observing runtime problems toward answering the product question:

> What actually changed in application behavior when this code was executed?

## Explicitly deferred

v0.0.6 does not yet add:

- automatic baseline selection such as `last`, `main`, or `gold`;
- remote baseline storage or lookup;
- metric-aware `regressed` / `improved` classification;
- thresholds or percentage comparison;
- baseline-aware gate policy;
- ActiveRecord query regression or N+1 analysis;
- browser correlation;
- deeper PostgreSQL analysis;
- public RunWitness MCP tools;
- production correlation.

## Release gates

A v0.0.6 release is eligible only when:

1. all locked acceptance tests pass;
2. baseline comparison correctly classifies `new`, `resolved`, and `unchanged` Finding IDs;
3. missing or malformed requested baselines fail before target execution and Run creation;
4. baseline comparison does not change existing current-run gate semantics;
5. existing v0.0.1-v0.0.5 behavior remains compatible except the intentional version advance;
6. `go test ./...`, `go test -race ./...`, `go vet ./...`, and gofmt checks pass;
7. the established cross-compile matrix passes;
8. real upstream `tobert/otlp-mcp` interoperability still passes;
9. real Rails 8.1 / Ruby 3.4 interoperability still passes;
10. README and changelog describe explicit baseline comparison and its current limits;
11. `runwitness --version` reports exactly `RunWitness v0.0.6`;
12. successful `main` CI is eligible for an immutable `v0.0.6` tag at the exact successful CI commit.
