# RunWitness v0.0.7 Release Scope

Status: Release candidate contract

v0.0.7 makes the v0.0.6 baseline diff actionable by adding an explicit baseline-aware Finding gate scope.

## Stable public surface inherited from v0.0.6

All v0.0.6 behavior remains compatible except for the expected version string moving to v0.0.7:

- universal Run execution and Git/process capture;
- opt-in OpenTelemetry Evidence through `--otel`;
- explicit Rails runtime observation through `--rails`;
- normalized OpenTelemetry and Rails Evidence;
- semantic runtime Findings;
- deterministic cross-Run Finding identity;
- explicit local baseline selection through `--baseline <run_id>`;
- deterministic `new`, `resolved`, and `unchanged` Finding classification;
- reserved empty `regressed` and `improved` classes;
- target process exit-code preservation;
- verdict and CLI exit-code semantics;
- real upstream `otlp-mcp` interoperability gate;
- real Rails 8.1 / Ruby 3.4 interoperability gate.

## New stable surface in v0.0.7

A baseline-compared Run may opt into Finding gates that consider only newly introduced Findings:

```text
runwitness run --baseline <run_id> --gate-scope new -- <command> [args...]
```

The supported values are:

```text
all
new
```

`all` preserves the v0.0.6 absolute gate behavior and remains the default when `--gate-scope` is omitted.

When `--gate-scope` is explicitly supplied, the selected scope is recorded in baseline metadata:

```json
{
  "baseline": {
    "run_id": "<baseline-run-id>",
    "finding_gate_scope": "new"
  }
}
```

For `new` scope, existing Finding-based gate membership is filtered against `diff.new` after the finalized reliable baseline diff exists:

```text
eligible finding_ids = original finding_ids ∩ diff.new
```

The current Finding set and diff remain complete. Unchanged Findings stay visible in `findings` and `diff.unchanged`; they are not hidden or reclassified.

For the built-in `runtime.no_errors` gate:

- unchanged-only runtime Findings produce a passed scoped gate with an empty `finding_ids` list;
- current-only runtime Findings remain new and keep the gate triggered;
- resolved baseline Findings do not trigger a current gate.

## Reliability and failure semantics

Gate scoping does not weaken non-Finding failures.

- a non-zero target exit remains verdict `fail`;
- a RunWitness or required-adapter failure remains verdict `error`;
- gate scoping is applied only after a reliable baseline diff exists;
- explicit `--gate-scope` without `--baseline` is a usage error before target execution and Run creation;
- unknown, empty, or duplicate gate-scope values are usage errors before the Run boundary.

The CLI mapping remains:

```text
0 = pass or warn
1 = fail
2 = RunWitness error
```

## Why this release exists

v0.0.6 could answer what changed, but an unchanged known runtime problem still failed an absolute quality gate.

v0.0.7 adds the opt-in patch-validation question:

> Did this code change introduce a new behavioral problem?

Example:

```text
baseline: runtime.error A
current:  runtime.error A
                    ↓
               unchanged
                    ↓
          --gate-scope new
                    ↓
                  PASS
```

while a newly introduced problem still fails:

```text
baseline: clean
current:  runtime.error B
                    ↓
                   new
                    ↓
          --gate-scope new
                    ↓
                  FAIL
```

## Explicitly deferred

v0.0.7 does not yet add:

- automatic baseline selection such as `last`, `main`, or `gold`;
- remote baseline storage or lookup;
- metric-aware `regressed` / `improved` classification;
- configurable per-rule gate policies;
- threshold or percentage-based regression policy;
- ActiveRecord query regression or N+1 analysis;
- browser correlation;
- deeper PostgreSQL analysis;
- public RunWitness MCP tools;
- production correlation.

## Release gates

A v0.0.7 release is eligible only when:

1. all locked acceptance tests pass;
2. unchanged Findings remain visible but do not fail Finding-based gates under `--gate-scope new`;
3. new Findings continue to trigger their existing gates under `--gate-scope new`;
4. explicit `all` scope preserves v0.0.6 absolute gate behavior;
5. invalid gate-scope usage fails before target execution and Run creation;
6. target failures and RunWitness/instrumentation errors remain absolute;
7. existing v0.0.1-v0.0.6 behavior remains compatible except the intentional version advance;
8. `go test ./...`, `go test -race ./...`, `go vet ./...`, and gofmt checks pass;
9. the established cross-compile matrix passes;
10. real upstream `tobert/otlp-mcp` interoperability still passes;
11. real Rails 8.1 / Ruby 3.4 interoperability still passes;
12. README and changelog describe baseline-aware gate scope and its default-safe behavior;
13. `runwitness --version` reports exactly `RunWitness v0.0.7`;
14. successful `main` CI is eligible for an immutable `v0.0.7` tag at the exact successful CI commit.
