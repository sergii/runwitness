# RunWitness v0.0.4 Release Scope

Status: Release candidate contract

v0.0.4 is a semantic-correctness release for the Findings layer introduced in v0.0.3.

## Stable public surface inherited from v0.0.3

All v0.0.3 behavior remains compatible except for the expected version string moving to v0.0.4:

- `runwitness --version`;
- universal Run execution and Git/process capture;
- opt-in OpenTelemetry Evidence through `--otel`;
- normalized `otel.span`, `otel.log`, and `otel.metric` Evidence;
- `otel.span` status `ERROR` -> `runtime.error` Finding;
- `runtime.no_errors` fail gate;
- successful target exit code preserved when a runtime gate fails;
- CLI exit code `1` for verdict `fail`;
- real upstream `otlp-mcp` interoperability gate.

## New stable surface in v0.0.4

Finding identity is stable across Runs.

For the first `runtime.error` Finding rule, two independent Runs observing the same logical operation MUST produce the same `finding_id`, even when their:

- Run IDs differ;
- Evidence IDs differ;
- trace IDs differ;
- span IDs differ;
- timestamps differ.

The current stable fingerprint uses semantic inputs only:

- Finding kind;
- rule ID;
- OpenTelemetry service name when available;
- OpenTelemetry span name when available.

A different logical operation MUST be able to produce a different Finding ID.

Run-local Evidence references remain Run-local and are not replaced by the stable Finding identity.

## Version contract

The stable release reports:

```text
RunWitness v0.0.4
```

`--version` remains side-effect free and MUST NOT create a Run.

## Why this release exists

Stable Finding identity is required before baseline comparison can correctly classify Findings as:

```text
new
unchanged
resolved
regressed
improved
```

Without this invariant, the same logical problem would appear new in every Run.

## Explicitly deferred

v0.0.4 does not yet add:

- baseline selection or Run diffing;
- Ruby/Rails runtime instrumentation;
- browser correlation;
- PostgreSQL analysis;
- public RunWitness MCP tools;
- production correlation.

## Release gates

A v0.0.4 release is eligible only when:

1. all locked acceptance tests pass;
2. the same logical runtime error has the same Finding ID across independent Runs;
3. a different logical operation has a different Finding ID;
4. existing v0.0.1-v0.0.3 behavior remains compatible except the intentional version advance;
5. `go test ./...`, `go test -race ./...`, `go vet ./...`, and gofmt checks pass;
6. the established cross-compile matrix passes;
7. the real upstream `tobert/otlp-mcp` interoperability smoke test passes;
8. README and changelog describe the stable Finding identity guarantee;
9. `runwitness --version` reports exactly `RunWitness v0.0.4`.
