# RunWitness v0.0.11 Release Scope

Status: Stable

v0.0.11 turns the metric-aware Rails query-count comparison introduced in v0.0.10 into an explicit opt-in quality gate while preserving descriptive behavior by default.

## Stable public surface inherited from v0.0.10

All v0.0.10 behavior remains compatible except for the expected version advance and the new opt-in policy flag:

- universal Run execution and Git/process capture;
- opt-in OpenTelemetry Evidence through `--otel`;
- explicit Rails runtime observation through `--rails`;
- `Rails.error` Evidence and handled-error Findings;
- normalized `rails.sql` Evidence from relevant `sql.active_record` notifications;
- deterministic `database.query_count` Findings;
- metric-aware `regressed`, `improved`, and `unchanged` baseline comparison;
- explicit local baseline selection;
- baseline-aware Finding gate scope through `--gate-scope all|new`;
- local read-only MCP through `list_runs`, `get_run`, and `get_evidence`;
- target exit-code, verdict, and CLI exit semantics;
- real upstream `otlp-mcp` interoperability;
- real Rails 8.1 / Ruby 3.4 interoperability.

## New stable surface in v0.0.11

RunWitness accepts:

```bash
runwitness run \
  --rails \
  --baseline <run_id> \
  --fail-on-query-regression \
  -- bundle exec rspec
```

The flag requires an explicit baseline and is rejected before the Run boundary when no baseline is supplied.

When requested, RunWitness evaluates the finalized comparison state and adds the deterministic gate:

```text
rule_id = database.no_query_count_regressions
action  = fail
```

Eligible Findings are query-count Findings that are present in `diff.regressed`:

```text
kind    = database.query_count
rule_id = rails.sql.query_count
```

If one or more eligible Findings regressed, the gate is `triggered`, the Run verdict is `fail`, and RunWitness exits `1` while preserving the target process exit code.

If no eligible query-count Finding regressed, the requested gate remains visible with outcome `passed`, the Run keeps its otherwise-computed verdict, and the gate does not manufacture a failure.

## Gate-scope interaction

`--fail-on-query-regression` operates on comparison state, not on `diff.new`.

Therefore it is deliberately independent of:

```text
--gate-scope new
```

A stable query-count Finding that exists in both baseline and current Runs but moves from a lower count to a higher count is still eligible for the regression gate even though it is not a new Finding.

## Default behavior remains descriptive

Without `--fail-on-query-regression`, v0.0.10 behavior is preserved exactly:

- a query-count increase is classified in `diff.regressed`;
- the Finding severity may be `warning`;
- no database gate is added;
- an otherwise passing Run remains passing.

This preserves the invariant:

```text
Finding severity != gate action
```

## Version contract

The stable release reports exactly:

```text
RunWitness v0.0.11
```

`--version` remains side-effect free and does not create a Run.

## Explicitly deferred

v0.0.11 does not add:

- configurable query-regression thresholds;
- percentage-based or absolute query-count tolerances;
- N+1 classification;
- query-duration regression gates;
- SQL AST or literal-aware normalization;
- allocation or memory regression;
- PostgreSQL execution-plan analysis;
- automatic baseline selection;
- browser correlation;
- production correlation.

## Release gates

A v0.0.11 release is eligible only when:

1. all locked acceptance tests pass;
2. `--fail-on-query-regression` requires an explicit baseline before the Run boundary;
3. regressed Rails query-count Findings trigger `database.no_query_count_regressions` with action `fail`;
4. unchanged and improved query counts keep the requested gate visible as `passed`;
5. the comparison gate remains effective with `--gate-scope new`;
6. omitting the flag preserves v0.0.10 descriptive behavior exactly;
7. target process exit codes remain unchanged by gate policy;
8. RunWitness and observation `error` verdicts are never downgraded to `fail`;
9. existing v0.0.1-v0.0.10 behavior remains compatible except the version advance;
10. `go test ./...`, `go test -race ./...`, `go vet ./...`, and gofmt checks pass;
11. the established cross-compile matrix passes;
12. real upstream `tobert/otlp-mcp` interoperability passes;
13. real Rails 8.1 / Ruby 3.4 `Rails.error` and `sql.active_record` interoperability passes;
14. README and changelog document the opt-in query regression gate without implying that it is enabled by default;
15. `runwitness --version` reports exactly `RunWitness v0.0.11`;
16. successful `main` CI is eligible for an immutable `v0.0.11` tag at the exact successful CI commit.
