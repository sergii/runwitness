# RunWitness v0.0.10 Release Scope

Status: Stable

v0.0.10 adds Rails SQL query-count Evidence/Findings and the first metric-aware Run-to-Run comparison while deliberately keeping database policy descriptive rather than gating.

## Stable public surface inherited from v0.0.9

All v0.0.9 behavior remains compatible except for the expected version advance:

- universal Run execution and Git/process capture;
- opt-in OpenTelemetry Evidence through `--otel`;
- explicit Rails runtime observation through `--rails`;
- `Rails.error` Evidence and handled-error Findings;
- semantic runtime Findings and deterministic Finding identity;
- explicit local baseline selection;
- baseline-aware gate scope through `--gate-scope all|new`;
- local read-only MCP through `list_runs`, `get_run`, and `get_evidence`;
- target exit-code, verdict, and CLI exit semantics;
- real upstream `otlp-mcp` interoperability;
- real Rails 8.1 / Ruby 3.4 interoperability.

## New stable surface in v0.0.10

When `--rails` is enabled, relevant `sql.active_record` notifications become normalized `rails.sql` Evidence.

RunWitness groups whitespace-normalized SQL statements and derives deterministic Findings:

```text
kind     = database.query_count
rule_id  = rails.sql.query_count
severity = info
```

Cached queries, blank SQL, and notification names `SCHEMA` / `TRANSACTION` are ignored according to the locked feature contract.

The same normalized SQL statement keeps the same `finding_id` across independent Runs regardless of Run-local Evidence IDs or observed count.

With an explicit baseline, matched query-count Findings receive numeric comparison data:

```json
{
  "comparison": {
    "baseline": 1,
    "current": 3,
    "delta": 2,
    "delta_percent": 200.0,
    "unit": "queries"
  }
}
```

Classification becomes:

```text
current > baseline  -> regressed
current < baseline  -> improved
current = baseline  -> unchanged
```

A regressed query-count Finding has severity `warning`; improved and unchanged query-count Findings have severity `info`.

The existing `new` and `resolved` semantics continue to apply when a query pattern appears only on one side of the comparison.

## Verdict and policy boundary

v0.0.10 does not add a database quality gate or default regression threshold.

A query-count regression alone does not change an otherwise passing verdict or CLI exit code. This preserves the invariant:

```text
Finding severity != gate action
```

The release establishes trustworthy database Evidence and metric comparison before a later contract chooses policy.

## Version contract

The stable release reports exactly:

```text
RunWitness v0.0.10
```

`--version` remains side-effect free and does not create a Run.

## Why this release exists

v0.0.10 is the first RunWitness release that can show a behavioral performance change even when the target process and tests still pass:

```text
baseline query count       1
current query count        3
          |
          v
database.query_count
          |
          v
       regressed
```

This moves RunWitness beyond binary runtime-error detection toward deterministic before/after behavioral evidence for code changes.

## Explicitly deferred

v0.0.10 does not add:

- a database regression gate;
- configurable query-count thresholds;
- SQL literal scrubbing or AST normalization;
- N+1 classification;
- query-duration regression;
- allocation or memory regression;
- PostgreSQL execution-plan analysis;
- automatic baseline selection;
- browser correlation;
- production correlation.

## Release gates

A v0.0.10 release is eligible only when:

1. all locked acceptance tests pass;
2. Rails SQL events normalize to valid Evidence and stable query-count Findings;
3. cached/schema/transaction/blank SQL noise remains excluded;
4. query-count baseline comparison correctly and exclusively classifies `regressed`, `improved`, and `unchanged` Findings;
5. query regression alone does not create a database gate or alter an otherwise passing verdict;
6. existing v0.0.1-v0.0.9 behavior remains compatible except the version advance;
7. `go test ./...`, `go test -race ./...`, `go vet ./...`, and gofmt checks pass;
8. the established cross-compile matrix passes;
9. real upstream `tobert/otlp-mcp` interoperability still passes;
10. real Rails 8.1 / Ruby 3.4 `Rails.error` interoperability still passes;
11. real Rails 8.1 / Ruby 3.4 `sql.active_record` interoperability passes;
12. README and changelog document Rails SQL Evidence and metric comparison without claiming a database gate;
13. `runwitness --version` reports exactly `RunWitness v0.0.10`;
14. successful `main` CI is eligible for an immutable `v0.0.10` tag at the exact successful CI commit.
