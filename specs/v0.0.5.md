# RunWitness v0.0.5 Release Scope

Status: Release candidate contract

v0.0.5 is the first framework-specific runtime release. It adds Rails error reporting evidence on top of the universal Runner, OpenTelemetry Evidence, semantic Findings, and deterministic gates from v0.0.1-v0.0.4.

## Stable public surface inherited from v0.0.4

All v0.0.4 behavior remains compatible except for the expected version string moving to v0.0.5:

- `runwitness --version`;
- universal Run execution and Git/process capture;
- opt-in OpenTelemetry Evidence through `--otel`;
- normalized `otel.span`, `otel.log`, and `otel.metric` Evidence;
- `otel.span` status `ERROR` -> `runtime.error` Finding;
- deterministic cross-Run Finding identity;
- `runtime.no_errors` fail gate;
- successful target exit code preserved when a runtime gate fails;
- CLI exit code `1` for verdict `fail`;
- real upstream `otlp-mcp` interoperability gate.

## New stable surface in v0.0.5

RunWitness supports explicit Rails runtime observation:

```text
runwitness run --rails -- <command>
```

The Rails adapter MUST:

- integrate through the standard `Rails.error` reporter subscriber interface;
- preserve the target command and its original process exit code;
- normalize observed Rails error reports as `rails.error` Evidence;
- derive a deterministic `runtime.handled_error` Finding for handled Rails error reports;
- trigger the existing `runtime.no_errors` gate for such Findings;
- return RunWitness CLI exit `1` when the target exits `0` but the Rails runtime gate fails;
- return verdict `error` and CLI exit `2` when `--rails` was explicitly requested but Rails instrumentation could not be confirmed;
- remain outside the universal Runner core as a framework adapter.

The Rails adapter MUST preserve Run-local Evidence references while keeping semantic Finding identity independent of Run IDs and Evidence IDs.

## Real interoperability requirement

The release gate MUST execute RunWitness against a real Rails 8.1 runtime on Ruby 3.4 and prove that a handled `Rails.error` report:

1. leaves the target process exit code at `0`;
2. produces `rails.error` Evidence;
3. produces a `runtime.handled_error` Finding;
4. triggers `runtime.no_errors`;
5. makes the RunWitness CLI exit with code `1`.

A Rails-compatible fake fixture alone is not sufficient for release eligibility.

## Version contract

The stable release reports:

```text
RunWitness v0.0.5
```

`--version` remains side-effect free and MUST NOT create a Run.

## Why this release exists

The first product-level value proposition for RunWitness is a successful test command that still exposes a runtime problem:

```text
tests / target exit        0
Rails.error handled        1
          ↓
runtime.handled_error
          ↓
runtime.no_errors          FAIL
          ↓
RunWitness exit            1
```

This proves that process success and observed application behavior are separate facts.

## Explicitly deferred

v0.0.5 does not yet add:

- automatic Rails mode detection without `--rails`;
- ActiveRecord query regression or N+1 analysis;
- baseline selection or Run diffing;
- browser correlation;
- PostgreSQL analysis;
- public RunWitness MCP tools;
- production correlation.

## Release gates

A v0.0.5 release is eligible only when:

1. all locked acceptance tests pass;
2. the Rails.error contract passes without modifying its locked acceptance tests during implementation;
3. real Rails 8.1 / Ruby 3.4 interoperability passes;
4. real upstream `tobert/otlp-mcp` interoperability still passes;
5. existing v0.0.1-v0.0.4 behavior remains compatible except the intentional version advance;
6. `go test ./...`, `go test -race ./...`, `go vet ./...`, and gofmt checks pass;
7. the established cross-compile matrix passes;
8. README and changelog describe the Rails runtime contract;
9. `runwitness --version` reports exactly `RunWitness v0.0.5`;
10. successful `main` CI is eligible for an immutable `v0.0.5` tag at the exact successful CI commit.
