# RunWitness v0.0.2 Release Scope

Status: Release candidate contract

v0.0.2 keeps the stable v0.0.1 Runner core and adds the first runtime Evidence adapter: OpenTelemetry through a Run-owned `otlp-mcp` backend.

## Stable public surface inherited from v0.0.1

All v0.0.1 behavior remains compatible except for the expected version string moving to v0.0.2:

- `runwitness --version`
- `runwitness run [--label <name>] -- <command> [args...]`
- UUIDv7 Run identity
- `RUNWITNESS_RUN_ID` propagation
- exact argv preservation
- stdout/stderr capture
- process result and deterministic verdict mapping
- schema-valid `run.json`
- Git before/after state and complete tracked/untracked fingerprint
- exclusion of `.runwitness/` observer artifacts from observed Git state
- filesystem storage under `.runwitness/runs/<run_id>/`

## New stable surface in v0.0.2

OpenTelemetry observation is explicitly enabled with:

```text
runwitness run --otel -- <command> [args...]
```

The v0.0.2 compatibility contract includes:

- Run-owned `otlp-mcp` backend startup and shutdown;
- optional backend executable override via `RUNWITNESS_OTLP_MCP_BIN`;
- OTLP endpoint discovery through the backend MCP contract;
- start/end observation snapshots around target execution;
- exporter environment injection for the target process;
- preservation of existing `OTEL_RESOURCE_ATTRIBUTES`;
- exactly one `runwitness.run_id=<uuidv7>` resource attribute for the active Run;
- Evidence v1 records in `evidence.jsonl`;
- normalized `otel.span`, `otel.log`, and `otel.metric` Evidence kinds;
- `summary.evidence_count` equal to the number of Evidence records;
- `otel` adapter status in `run.json`;
- required-adapter error semantics when `--otel` is explicitly requested;
- target failure semantics remaining distinct from instrumentation failure.

The Evidence format is defined by `schemas/evidence-v1.schema.json`.

## Version contract

The stable release reports:

```text
RunWitness v0.0.2
```

`--version` remains side-effect free and MUST NOT create a Run.

## Explicitly deferred

v0.0.2 does not add:

- an OTLP collector implemented by RunWitness;
- application-language auto-instrumentation;
- Findings derived from OpenTelemetry Evidence;
- quality gates over telemetry;
- baseline selection or Run diffing;
- Ruby/Rails-specific runtime evidence;
- browser correlation;
- PostgreSQL analysis;
- MCP as a public RunWitness interface;
- production correlation;
- already-running remote/server process correlation.

## Release gates

A v0.0.2 tag is eligible only when:

1. all locked acceptance tests pass;
2. every v0.0.1 compatibility test still passes except the intentionally advanced version string;
3. OpenTelemetry acceptance cases pass without modifying their locked contract in the implementation/release PR;
4. `go test ./...`, `go test -race ./...`, `go vet ./...`, and gofmt checks pass;
5. the Runner cross-compiles for the established v0.0.1 target matrix;
6. an integration smoke test succeeds against the real upstream `tobert/otlp-mcp` executable, proving MCP startup, endpoint discovery, snapshots, a zero-Evidence observed Run, and clean shutdown;
7. README and changelog describe the v0.0.2 CLI and external `otlp-mcp` dependency accurately;
8. `runwitness --version` reports exactly `RunWitness v0.0.2`.

The real-backend smoke test does not replace the deterministic fake-backend acceptance suite. The fake backend locks the RunWitness contract; the real backend test detects upstream interoperability drift.
