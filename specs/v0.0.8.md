# RunWitness v0.0.8 Release Scope

Status: Stable

v0.0.8 adds the first public agent-native read surface over the canonical local Run store through MCP.

## Stable public surface inherited from v0.0.7

All v0.0.7 behavior remains compatible except for the expected version string moving to v0.0.8:

- universal Run execution and Git/process capture;
- opt-in OpenTelemetry Evidence through `--otel`;
- explicit Rails runtime observation through `--rails`;
- normalized OpenTelemetry and Rails Evidence;
- semantic runtime Findings;
- deterministic cross-Run Finding identity;
- explicit local baseline selection through `--baseline <run_id>`;
- deterministic `new`, `resolved`, and `unchanged` Finding classification;
- baseline-aware Finding gate scope through `--gate-scope all|new`;
- target process exit-code preservation;
- verdict and CLI exit-code semantics;
- real upstream `otlp-mcp` interoperability gate;
- real Rails 8.1 / Ruby 3.4 interoperability gate.

## New stable surface in v0.0.8

RunWitness exposes a local stdio MCP server:

```text
runwitness mcp
```

The first public RunWitness MCP tool surface is read-only and contains exactly:

```text
list_runs
get_run
```

`list_runs` provides deterministic newest-first discovery summaries from the local Run store. `get_run` returns one canonical decoded `run.json` document by UUIDv7 Run ID.

Successful tool calls provide machine-readable `structuredContent`. Tool failures are MCP tool errors rather than RunWitness application verdicts and do not terminate a healthy server.

The MCP adapter is deliberately thin. It does not create Runs, execute target commands, reinterpret Findings, hide gates or diffs, or introduce a second semantic model.

## Locality and security boundary

The MCP server reads only:

```text
<cwd>/.runwitness/runs/
```

v0.0.8 remains local stdio only.

It does not:

- bind a network listener;
- expose arbitrary filesystem reads;
- follow Run-store symlink escapes;
- mutate Run artifacts;
- create or delete Runs;
- expose a tool that executes commands.

An absent Run store is a valid empty store and querying it does not create `.runwitness/`.

Malformed Run data is reported rather than silently omitted from discovery.

## Version contract

The stable release reports:

```text
RunWitness v0.0.8
```

`--version` remains side-effect free and MUST NOT create a Run.

Starting and using `runwitness mcp` MUST also remain side-effect free with respect to Run creation.

## Why this release exists

The RunWitness CLI already records deterministic runtime evidence for humans and CI. v0.0.8 makes the same canonical evidence directly readable by coding agents through a standard protocol.

The important invariant is:

```text
CLI / CI / agent
      |
      v
same canonical Run model
```

An agent can now ask what Runs exist and inspect an exact Run without scraping terminal prose or receiving a separately interpreted representation.

This is the first public step toward an agent-native runtime verification loop while keeping execution authority outside MCP.

## Explicitly deferred

v0.0.8 does not yet add:

- an MCP tool that starts a Run;
- raw Evidence pagination or search through MCP;
- stdout/stderr retrieval through MCP;
- automatic baseline selection such as `last`, `main`, or `gold`;
- remote Run storage or lookup;
- MCP resources or prompts;
- metric-aware `regressed` / `improved` comparison;
- ActiveRecord query regression or N+1 analysis;
- browser correlation;
- deeper PostgreSQL analysis;
- production correlation.

## Release gates

A v0.0.8 release is eligible only when:

1. all locked acceptance tests pass;
2. `runwitness mcp` interoperates over MCP stdio using the locked protocol contract;
3. `tools/list` exposes the locked `list_runs` and `get_run` surface;
4. `list_runs` provides deterministic newest-first summaries and handles an absent store without mutation;
5. `get_run` returns the canonical stored Run document for a valid UUIDv7 Run ID;
6. invalid tool input and malformed local Run data remain tool errors without terminating the MCP server;
7. the MCP path does not create Runs, execute commands, or allow arbitrary filesystem traversal;
8. existing v0.0.1-v0.0.7 behavior remains compatible except the intentional version advance;
9. `go test ./...`, `go test -race ./...`, `go vet ./...`, and gofmt checks pass;
10. the established cross-compile matrix passes;
11. real upstream `tobert/otlp-mcp` interoperability still passes;
12. real Rails 8.1 / Ruby 3.4 interoperability still passes;
13. README and changelog describe the MCP read surface and its local read-only security boundary;
14. `runwitness --version` reports exactly `RunWitness v0.0.8`;
15. successful `main` CI is eligible for an immutable `v0.0.8` tag at the exact successful CI commit.
