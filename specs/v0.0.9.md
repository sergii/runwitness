# RunWitness v0.0.9 Release Scope

Status: Release candidate contract

v0.0.9 extends the stable local read-only MCP surface so coding agents can dereference a Finding's `evidence_refs` to the exact normalized Evidence v1 record that produced it.

## Stable public surface inherited from v0.0.8

All v0.0.8 behavior remains compatible except for the intentional MCP tool-surface extension and expected version advance:

- universal Run execution and Git/process capture;
- opt-in OpenTelemetry Evidence through `--otel`;
- explicit Rails runtime observation through `--rails`;
- semantic runtime Findings and deterministic Finding identity;
- explicit local baseline selection and `new` / `resolved` / `unchanged` diffing;
- baseline-aware gate scope through `--gate-scope all|new`;
- local stdio MCP access through `list_runs` and `get_run`;
- target exit-code, verdict, and CLI exit semantics;
- real upstream `otlp-mcp` and real Rails 8.1 / Ruby 3.4 interoperability gates.

## New stable surface in v0.0.9

The public RunWitness MCP tool surface contains exactly:

```text
list_runs
get_run
get_evidence
```

`get_evidence(run_id, evidence_id)` resolves one Run-local Evidence record from:

```text
<cwd>/.runwitness/runs/<run_id>/evidence.jsonl
```

It returns the exact decoded normalized Evidence object through MCP `structuredContent` without reinterpretation, summarization, enrichment, or field omission.

The requested Run must satisfy the existing canonical `get_run` boundary. Evidence validation rejects invalid identifiers, malformed records, cross-Run records, duplicate Evidence IDs, missing Evidence, non-regular files, and symlink escapes. Tool errors do not terminate an otherwise healthy MCP server.

## Version contract

The stable release reports exactly:

```text
RunWitness v0.0.9
```

`--version` remains side-effect free and does not create a Run.

## Why this release exists

v0.0.8 let an agent discover and inspect Runs. v0.0.9 closes the first semantic read chain:

```text
Run
 |
 v
Finding
 |
 v evidence_refs
Evidence
```

This gives agents access to both RunWitness conclusions and the exact normalized observation supporting those conclusions while keeping MCP read-only and local.

## Explicitly deferred

v0.0.9 does not add:

- Evidence listing, filtering, pagination, or search;
- stdout/stderr retrieval through MCP;
- an MCP tool that executes a Run;
- automatic baseline selection;
- remote Run stores;
- MCP resources or prompts;
- metric-aware `regressed` / `improved` comparison;
- ActiveRecord query regression or N+1 analysis;
- browser correlation;
- deeper PostgreSQL analysis;
- production correlation.

## Release gates

A v0.0.9 release is eligible only when:

1. all locked acceptance tests pass;
2. `tools/list` exposes exactly `list_runs`, `get_run`, and `get_evidence`;
3. `get_evidence` returns the exact canonical normalized Evidence record;
4. Finding `evidence_refs` can be dereferenced through `get_evidence`;
5. malformed, cross-Run, duplicate, invalid, and missing Evidence remain tool errors without terminating the MCP server;
6. MCP Evidence reads do not mutate the Run store or expand execution/network authority;
7. existing v0.0.1-v0.0.8 behavior remains compatible except the intentional MCP surface and version advance;
8. `go test ./...`, `go test -race ./...`, `go vet ./...`, and gofmt checks pass;
9. the established cross-compile matrix passes;
10. real upstream `tobert/otlp-mcp` interoperability still passes;
11. real Rails 8.1 / Ruby 3.4 interoperability still passes;
12. README and changelog document `get_evidence` and the Run -> Finding -> Evidence flow;
13. `runwitness --version` reports exactly `RunWitness v0.0.9`;
14. successful `main` CI is eligible for an immutable `v0.0.9` tag at the exact successful CI commit.
